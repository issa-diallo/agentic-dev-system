# PRD — Optimisation Codex de la méthode

PRD: PASS

## Problème et utilisateurs
Les agents et mainteneurs de projets héritent d'une entrée longue et de lectures
systématiques, sans contrat complet de délégation ni preuve de portabilité des
optimisations. Rendre la méthode ciblée, économique et vérifiable pour petits
projets, applications standard et dépôts multi-applications.

## Périmètre
Navigation conditionnelle, politique de modèles, contrats des trois rôles,
compaction, estimation qualitative et héritage testé via l'installateur existant.
Évaluer quatre outils tiers sans installation. Conserver toutes les gates,
Gitmoji, DoR/DoD, sécurité et personnalisation. Aucun framework, stack imposée,
modèle figé, quota inventé ou merge automatique.

## Critères de succès
Entrée AGENTS plus courte en octets ; liens locaux résolus ; générations LIGHT
et LARGE testées ; trois modes d'installation préservés ; CI et revue indépendante
réussies ; PR vers main ouverte avec preuves et rollback.

## Contraintes et risques
Markdown + Bash + tests Python standard, sans nouvelle dépendance d'exécution.
Auth applicative et tenant sans objet ; secrets GitHub jamais affichés.
Publication de branche/PR autorisée par la mission ; merge réservé à l'humain.
Risques : perte de règle, référence cassée, personnalisation écrasée, métrique
commerciale prise pour une preuve. Tests et revue doivent les couvrir.
Le guide fourni (guide_limites_gpt6_astra_agence_agentique.pdf, 16 pages) est
analysé par recommandation ; ses chiffres ne sont pas des mesures de ce dépôt.

Verdict : PASS
